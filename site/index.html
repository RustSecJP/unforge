When you'll use it

01

A strange binary turned up on a server

Before anyone runs it, open it. Which crates does it pull in: networking, crypto, process control? What strings and panic messages does it carry? What does main actually do? A first answer in minutes, without a sandbox.

02

Checking what a binary really ships

Your SBOM and Cargo.lock say one thing; the release binary is what users get. See every crate and version compiled in, and the exact compiler commit that built it, from the file alone. Handy for supply-chain reviews and third-party tools you didn't build.

03

Analyzing Rust malware

In general-purpose tools, Rust malware is a wall of mangled names and inlined standard library. Mekiki separates the author's code from crates and std, names functions in stripped files with fingerprints, and shows Windows imports by name.

04

Learning how Rust compiles

Write ten lines, build them, open the result. See what Option, iterators, ? and generics become, function by function, with the source panic locations written beside the code.

Features

Symbol Tree by crate

Functions grouped into your program, each crate with its version, the standard library, and unknown.

Listing

Code in address order with disassembly, function headers and clickable references. Back and forward like a browser.

Decompile

Readable Rust-style or C-style code for any function, with panic locations and string contents noted. Ghidra's decompiler, built in.

Inspector

Details for whatever you select. Crates link straight to crates.io and docs.rs.

Tables

Functions, Crates and Warnings, sortable and filterable. Odd file layouts are reported, not hidden.

Go to anything

Press G and type an address, a function, a section or a crate.

Fingerprints

Name functions in stripped binaries with fingerprint databases, or add files you trust to your own.

Windows files too

PE .exe and .dll, with imports shown by name in the code: kernel32.dll!CreateFileW.

How it works

Mekiki is built on unforge, a set of Rust libraries that read ELF and PE files without panicking, even when the file is broken or made hostile on purpose. unforge finds the functions and works out which crate each belongs to from the paths and symbols the compiler leaves behind, then disassembles them with iced-x86.

The decompile view comes from Ghidra's C++ decompiler, compiled into a small helper that Mekiki starts only when you need it. The app itself is a Tauri window.

  1. ReadParse the ELF or PE, report anything unusual.
  2. AttributeFind functions and the crate and version each came from.
  3. Disassemblex86-64 and x86 instructions, with names for calls.
  4. DecompileOn demand, one function at a time, in a separate process.

Install

macOS

Open Mekiki-macos-universal.dmg and drag Mekiki to Applications. It runs on Apple silicon and Intel.

The app is not signed with an Apple certificate. The first time, right-click Mekiki in Applications, choose Open, then Open again. If macOS says it "is damaged", run once:

xattr -dr com.apple.quarantine /Applications/Mekiki.app

Linux

AppImage, any distribution:

chmod +x Mekiki-linux-x86_64.AppImage
./Mekiki-linux-x86_64.AppImage

Debian / Ubuntu:

sudo apt install ./Mekiki-linux-amd64.deb

Windows

Run Mekiki-windows-x64-setup.exe. If SmartScreen says the publisher is unknown, choose More info, then Run anyway.

Then open a file with File → Open or drop it on the window. Help → Tutorial walks you through it using Mekiki's own executable.

Checksums for every file are in SHA256SUMS on the release page. Prefer the command line? The unforge CLI archives are there too.

Everything runs locally

Mekiki never uploads your files and does not phone home. It reads the file and never executes it. The decompiler runs in its own process, so a file built to confuse it cannot take the app down. No account, no telemetry.

FAQ

Does Mekiki run the binary?

No. It only reads the bytes of the file.

Which files can it open?

Linux ELF and Windows PE (.exe, .dll) for x86-64 and x86. Rust binaries get the most out of it: crates, versions and panic notes. Other programs open too, with less detail.

Does it work on stripped binaries?

Yes. Crates and versions are still found from the paths the compiler leaves in the file, and fingerprint databases can put names back on functions.

Do I need Ghidra or Java?

No. The Ghidra decompiler is built into Mekiki as a small native helper. Nothing else to install.

Why is the macOS app unsigned?

Signing needs a paid Apple account. Every file is built by GitHub Actions from the public repository; check it against SHA256SUMS, or build Mekiki from source.

Is it free?

Yes. Mekiki is open source under MIT or Apache-2.0. The bundled Ghidra decompiler is Apache-2.0.
